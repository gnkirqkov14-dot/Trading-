# Ръчни стъпки — какво трябва да направиш ти

Този файл е за **собственика на сайта**, не за програмист. Тук стоят
всички неща, които аз не мога да направя от кода — защото изискват
твой акаунт, твоя карта или натискане на бутон в чужд сайт.

Файлът се допълва при всяка нова такава стъпка. Ако си забравил нещо —
гледай тук, не в чата.

> ⚠️ **Никога не пиши ключове и пароли в чата.** Нито API ключове, нито
> данни на карта, нито резервни кодове. Те се въвеждат директно в
> съответния сайт (Vercel, Supabase). Ако случайно си поставил ключ
> някъде публично — изтрий го от там и си направи нов от същото място,
> откъдето си го взел.

## A. Чака те сега

### A1. Включи AI помощника (`ANTHROPIC_API_KEY`)

Плаващото 3D копче долу вдясно вече стои на сайта и се натиска, но
чатът няма да отговаря, докато няма ключ. Дотогава панелът показва само
преки пътища из сайта.

1. Отвори **console.anthropic.com** → регистрирай се.
2. **Billing** → добави карта и купи кредити. Минимумът е около $5.
3. Пак там намери **Usage limits** → задай месечен таван (например $10).
   **Направи това.** Това е спирачката, ако нещо тръгне не както трябва.
4. **API keys** → **Create Key** → копирай ключа.
   Показва се **само веднъж** — ако го затвориш, правиш нов.
5. Vercel → проекта → **Settings** → **Environment Variables** → **Add**:
   - Key: `ANTHROPIC_API_KEY`
   - Value: ключа
   - Type: **Secret** (не Config! Config значи „не е тайна")
   - Environment: **Production**
   - **Save**
6. По избор, същото още веднъж:
   - Key: `ASSISTANT_IP_SALT`
   - Value: произволен низ, например `imotpoint-2026-xk39`
   - Type: **Secret**
7. **Deployments** → трите точки на най-горния ред → **Redeploy**.

Без стъпка 7 нищо не се променя — Vercel чете променливите при deploy,
не постоянно.

**Колко струва:** около 4 стотинки на въпрос. 100 въпроса ≈ 7 лв.
Един посетител може да зададе най-много 20 въпроса на денонощие.

### A2. Качи петте снимки за началната страница

**Сцената вече работи на живо** — снимките се четат направо от адреса
им в Higgsfield, защото аз не мога да ги сваля (мрежата ми го блокира).
Тоест няма нищо спешно.

⚠️ **Но си струва да се направи.** Докато снимките висят на чужд сървър,
най-важната картина на сайта зависи от този акаунт. Спре ли той или
сменят ли се адресите, началната страница остава без фон. Щом ги качиш в
repo-то, стават наши и нищо външно не може да ги махне:

1. Отвори Higgsfield → галерията с петте кадъра → свали всеки един.
2. Преименувай ги **точно** така, по реда на историята:
   `01.png` (празна долина), `02.png` (една къща), `03.png` (махала),
   `04.png` (градче), `05.png` (днешен град).
3. GitHub → repo-то `Trading-` → влез в папка `property-platform` →
   после в `public` → бутон **Add file** → **Upload files** → пусни
   петте вътре → долу **Commit changes**.
   *(Ако папка `hero` я няма, при качването напиши `hero/01.png` в
   името на първия файл — GitHub сам създава папката.)*
4. Кажи ми, че са качени. Пренасочвам кода към тях и чуждият адрес
   отпада.

### A3. Провери дали Vercel Analytics е включен

Кодът е в сайта, но има и бутон в таблото, без който не се записват данни.

Vercel → проекта → таб **Analytics**. Ако пише **Enable** — натисни го.
Ако вече показва графика с посетители, значи е готово.

### A4. Данни за фактуриране във Vercel

Vercel показва „Action Required: billing address missing or incomplete".
Vercel → снимката на профила горе вдясно → **Settings** → **Billing** →
попълни адреса. Не е спешно, но рано или късно ще спре нещо.

### A5. Провери дали `CRON_SECRET` е зададен

Това пази автоматичната задача, която всеки ден маркира старите обяви
(напомняне на 7-ия ден, „Неактуална" на 14-ия, архивиране на 21-ия).

Vercel → проекта → **Settings** → **Environment Variables**. Търсиш
`CRON_SECRET` в списъка. Ако го няма:
- **Add** → Key: `CRON_SECRET`, Value: произволен таен низ,
  Type: **Secret**, Environment: **Production** → Save → Redeploy.

Без него задачата пак работи, но всеки в интернет може да я стартира.

### A6. Провери дали имаш admin права

Admin панелът е на `imotpoint.com/admin` — оттам виждаш всички обяви,
сигналите за агенции и можеш да блокираш.

Отвори адреса. Ако те върне назад, значи правата не са дадени.
Тогава: Supabase → **SQL Editor** → постави това (със **своя** имейл) → **Run**:

```sql
update public.profiles set is_admin = true
where id = (select id from auth.users where email = 'твоя@имейл.com');
```

### A7. Facebook пиксел — включи го и го провери

Кодът е в сайта, но пикселът не тръгва, докато номерът му не е зададен
във Vercel. Номерът **не е таен** (вижда се в кода на всяка страница),
затова е обикновена променлива, не Secret.

1. Vercel → проекта → **Settings** → **Environment Variables** → **Add**:
   - Key: `NEXT_PUBLIC_FB_PIXEL_ID`
   - Value: `1837636510591290`
   - Type: **Config** (не Secret)
   - Environment: отметни **Production** и **Preview**
   - **Save**
2. **Deployments** → трите точки на най-горния ред → **Redeploy**,
   с **махната** отметка „Use existing Build Cache".
   *(Без това нищо не се променя — такива променливи се запичат при
   build, не се четат постоянно.)*
3. Инсталирай разширението **Meta Pixel Helper** в Chrome, отвори
   imotpoint.com → иконката трябва да светне зелено и да показва
   един пиксел, едно събитие `PageView`.
4. Events Manager → dataset „Imot Point" → таб **Test events** →
   докато си на сайта, събитията трябва да се появяват на живо.
   Пробвай: отвори обява (`ViewContent`), направи търсене (`Search`).
5. След 20–30 минути в **Overview** трябва да има Total events > 0.

**Какво брои пикселът:** отваряне на страница, отваряне на обява,
търсене, регистрация, публикувана обява, натиснат телефон.
⚠️ Регистрациите **през Google** не се броят — техническо ограничение,
описано в CLAUDE.md. Броят се само тези с имейл и парола.

### A8. Преди да пуснеш реклами във Facebook

1. Business Settings → **Brand Safety** → **Domains** → добави
   `imotpoint.com` и го верифицирай (Meta дава DNS TXT запис —
   добавя се във Vercel → акаунт → Domains → домейна → DNS Records,
   същото място като за Google Search Console).
2. Events Manager → **Aggregated Event Measurement** → подреди до 8
   събития по важност. Най-горе сложи **Lead** (публикувана обява) или
   **CompleteRegistration**. Това решава кое събитие вижда Meta за
   потребители на iPhone, които са отказали проследяване.

### A9. ⚠️ Бисквитки и съгласие — реши какво правим

Досега сайтът нямаше нужда от онази досадна лента „Приемам бисквитки",
защото броячът на посетители (Vercel Analytics) не слага бисквитки.

**Facebook пикселът слага бисквитка и праща данни на Meta.** По
европейските правила (GDPR и чл. 4б от Закона за електронните
съобщения) за това се иска **предварително съгласие** от посетителя.
Сега пикселът тръгва веднага, без да пита.

Какво значи на практика:
- Рискът е глоба от Комисията за защита на личните данни. Малък сайт
  рядко е първи в списъка им, но рискът не е нула и расте с трафика.
- Поправката е лента при първо влизане с два бутона („Приемам" /
  „Само необходимите"), а пикселът тръгва само при „Приемам".
  Цената: част от хората отказват и рекламите виждат по-малко данни.

Кажи ми кое избираш. Ако искаш лентата — правя я; в кода е
подготвено едно място, което трябва да се промени.

## C. Ако някой ден смениш домейна пак

Смяната пипа **8 места**. Ако пропуснеш някое, сайтът изглежда работещ,
но нещо тихо се чупи (най-често входът с Google).

**Преди да купиш домейн — провери историята му.** Веднъж вече загубихме
купен домейн (`imotami.com`), защото Chrome го показваше с червен екран
„Опасен сайт" заради предишния му собственик. Двете проверки:

1. `transparencyreport.google.com/safe-browsing/search?url=ДОМЕЙН`
   — трябва да пише „Няма налични данни".
2. `web.archive.org/web/2020*/ДОМЕЙН`
   — трябва да пише „has not archived that URL".

Ако и двете са чисти, домейнът е безопасен. След покупката:

1. Vercel → акаунт → **Domains** → отвори домейна → **Connected Projects**
   → **Connect** → празно поле → избери проекта.
   *(Само покупката не стига — домейнът се купува на ниво акаунт.)*
2. Vercel → проекта → Environment Variables → `NEXT_PUBLIC_SITE_URL`
   → **Edit** (не Add — вече съществува) → новия адрес.
3. Кажи ми да сменя адреса в кода (има го на 7 места).
4. Supabase → Authentication → **URL Configuration** → Site URL и
   Redirect URLs. **Без тази стъпка входът с Google се чупи.**
5. Resend → Domains → добави новия домейн → **Auto configure** → изчакай
   да стане **Verified** (около час) → смени `RESEND_FROM_EMAIL` във Vercel.
6. Google Search Console → ново property → верификация → подай
   `https://новия-домейн.com/sitemap.xml` (пълния адрес, не само
   `sitemap.xml` — иначе дава „Невалиден адрес на Sitemap").
7. Vercel → Deployments → ⋯ → **Redeploy**, с **махната** отметка
   „Use existing Build Cache". Без това стъпки 2 и 3 не стигат до сайта.
8. Рекламните материали: корица и профилна снимка във Facebook, био
   текстовете, TikTok.

## E. Какво съм отказвал и защо

Пази го тук, за да не се връща темата наново.

- **Завишен (измислен) брояч на обяви.** Показването на неверни числа
  пред клиенти е заблуждаваща търговска практика по Закона за защита на
  потребителите, а числото се опровергава само̀ в мига, в който някой
  направи търсене. Приемливият вариант е истински брояч, скрит докато
  обявите не станат достатъчно.
- **Старите домейни да пренасочват към новия** — ти самият поиска да не
  го правим и е записано, за да не се случи по погрешка.
