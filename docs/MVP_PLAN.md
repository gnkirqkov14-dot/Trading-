# План за MVP

## Какво е построено в тази демо версия (Фаза 0)

Това, което вече е в репото и работи end-to-end (проверено ръчно —
бекенд + фронтенд едновременно, `POST /analyze/run` произвежда реални
решения и сделки):

- [x] Watchlist от 5 актива: BTC, ETH, SOL (крипто) + SPY, QQQ (ETF)
- [x] Технически анализ с реални безплатни данни (CoinGecko / Stooq),
      с прозрачен synthetic fallback при недостъпна мрежа
- [x] Новини + изказвания модул с реалистични mock данни, тагнати със
      sentiment/relevance/tone/importance (adapter-готов за реален API)
- [x] Модул за решения: претеглена комбинация от трите входа + Claude API
      за естествено-езикова, претеглена обосновка (с rule-based fallback)
- [x] Paper trading engine: cash от история на сделките, позиции с
      среднопретеглена цена, автоматичен stop-loss/take-profit
- [x] Dashboard: обща стойност, P&L, графика във времето, таблица с позиции
- [x] Дневник на решенията: всяко решение (вкл. "hold") с пълна обосновка
      и разгъваеми сигнали
- [x] Настройки за риск: max position %, SL/TP по подразбиране, и
      превключвател за бъдещия approval mode (вижте ARCHITECTURE.md, т.4)
- [x] Scheduler (APScheduler) за периодичен автоматичен анализ

## Следващи фази

### Фаза 1 — Реални данни за новини/изказвания
Замяна на mock модулите с реален безплатен/евтин доставчик:
- Новини: GNews или Mediastack (100-500 заявки/ден безплатно) вместо
  скъпия NewsAPI.org Business план
- Изказвания: TwitterAPI.io / Sorsa / SocialData вместо официалния X API
  (30-100x по-евтино за curated списък с ключови фигури)
- Работа: имплементиране на `_fetch_real_news` / `_fetch_real_statements`
  в `app/modules/news.py` и `app/modules/statements.py`; ключовете вече
  се четат от `.env` (`NEWS_API_KEY`, `STATEMENTS_API_KEY`).

### Фаза 2 — По-богат watchlist и по-фин технически анализ
- Разширяване на `WATCHLIST` с повече монети/ETF-и по избор на потребителя
- Разпознаване на свещни формации (не само SMA/RSI/MACD/S-R)
- TradingView widget вграждане в дашборда за визуален чарт (вместо/успоредно
  с Recharts)

### Фаза 3 — Активиране на approval mode
- UI поток за преглед и одобрение/отхвърляне на чакащи решения
  (`requires_approval = true` записите вече съществуват в дневника)
- Известия (email/push) при ново решение над прага
- `POST /decisions/{id}/approve` и `POST /decisions/{id}/reject` endpoints

### Фаза 4 — Path към реална търговия (изисква лицензиране)
Извън обхвата на демото — вижте `docs/REGULATORY_NOTES.md`. Изисква
интеграция с лицензиран брокер/борса, KYC/AML поток, и вероятно
инвестиционен посредник лиценз, ако услугата се предлага на трети лица.

## Приоритизация (какво да се build-не първо, ако се тръгва от нулата)

1. Paper portfolio engine + модел на данни (Position/Trade/Decision) —
   всичко останало зависи от него
2. Технически анализ модул с реални безплатни данни — дава на демото
   истински пазарен контекст без разходи
3. Decision engine с rule-based fallback — работещ агент без нужда от
   платен LLM ключ
4. Dashboard (портфейл + позиции) — видим резултат възможно най-рано
5. Mock новини/изказвания — добавят "защо" зад решенията без бюджет
6. Дневник на решенията + Claude reasoning — превръща сигналите в
   разбираема обосновка
7. Настройки за риск + approval-mode скелет — готовност за бъдещето, без
   да блокира демото
